# Plans (added 2026-10-13)
- **Show the plan first.** Before changing files or doing any multi-step work, show me the plan and wait for my OK. Quick questions get a direct answer with no plan. Routine writes a project's own rules already require (like the journal and its commits) don't need a plan either.
- **Format:** big categories as headings `### A. Name`, `### B. Name`. The steps under each category as a numbered list 1, 2, 3, one short line each.
- **Save every plan** to `.brain/plans.md` at the project root (create it if missing), newest plan first, with each step as a checkbox `- [ ]`. I often ask for one step at a time: do only that step, check it off, and leave the rest in the file so we can come back to it. When a whole plan is done, delete it from the file. If I put a step on hold, mark it "(on hold)" instead of deleting it.
- **Bring it back:** at the start of a session, if `.brain/plans.md` has unchecked steps, mention them in one line. When I ask "what's left?" or "the plan", show the unchecked steps.
