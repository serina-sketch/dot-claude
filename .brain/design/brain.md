# How the brain works

*What I want the brain to be, and every decision about it, with the date and why.*

## What I want
- A brain in every project that keeps track of what I'm working on, what I want to make, the decisions I made and the ideas I had, so any chat, on any device, can catch up from it.
- It's the modes' notes made always on. I liked how the modes kept track of what I did and what I'm working on, and I want that in every chat, not only when a mode is on (2026-10-13).

## Decisions
- **Written live, not rebuilt from chats (2026-10-13):** Claude writes to the brain during the chat. Chat transcripts are not read, because a brain that's kept up to date makes them redundant.
- **Organized by the AI (2026-10-13):** the AI decides how to split and name the files. `index.md` always says what each file and folder is for.
- **One brain per project (2026-10-13):** each project has its own `.brain/` in its own repo, so it follows the project to any device.
- **Only my decisions (2026-10-13):** the brain records what I worked on and decided. Suggestions from Claude go in only if I took them.
- **No log (2026-10-14):** there's no dated log of what I did. `design/` already collects every decision with its date, so a log would repeat it.
- **Design keeps every detail (2026-10-14):** every design detail I tell Claude goes into `design/`, in detail, even if it isn't useful right away.
- ~~**How Claude works goes in design (2026-10-14):** for example "sexual content is part of this project, don't flag it".~~ Replaced 2026-10-14: rules for how Claude works go in the project's CLAUDE.md, not the brain. The adult-content rule went into the global CLAUDE.md, because I don't want to hear about it in any project.
- ~~**No separate now file (2026-10-14):** what I'm working on is a **Now** section at the top of the plans.~~ Replaced 2026-10-14: no Now at all. Now is just the chat. `plans/index.md` keeps one status line per plan.
- **Plans get their own folder (2026-10-14):** a big project can have several big plans at once, so each plan is its own file in `plans/`, and `plans/index.md` lists the plans with their status.
- **Ideas get their own folder (2026-10-14):** `ideas/` holds every idea I give. `design/` is only for what I decided and what I want to make.
- **Backlog dropped (2026-10-14):** a backlog item is just something I'll do later, and two "not yet" places would make chats guess. Its items moved into `ideas/`, and "put it in backlog" now makes a plan marked "later".
- **Reversals keep history (2026-10-14):** when I change my mind, the old line stays, crossed out and marked "Replaced (date)", with the new decision next to it. Nothing is deleted, so a future chat knows what was already tried.
- **Idea statuses (2026-10-14):** an idea with no status is still just an idea, brainstorming. Then planned, done or dropped, with the history kept on one line ("planned 10-14 → dropped 10-16 (reason)"), because things will go back and forth between planned and rejected. Ideas stay the separate thing plans are made from.
- **"Later" means a plan with no steps (2026-10-14):** once I've decided to do something, it's concrete, so it becomes a plan file marked "later, no steps yet", and the idea gets "planned". Ideas = maybe, plans = decided.
- **When a plan is dropped (2026-10-14):** its file is deleted. The idea keeps the history and the reason, and any decisions are already in `design/`.
- **Thoughts folder (2026-10-14):** questions I ask while working aren't noise. Some of them eventually become useful, like in my thought network. So they go in `thoughts/`, and the flow is thoughts → ideas → plans → design. Each entry says where it came from.
- **What's not recorded (2026-10-14):** only debugging back-and-forth and in-between tweaks. For a tweak, only the final behavior goes into design.
- **Knowledge folder (2026-10-14):** research results are knowledge, kept in `knowledge/` with the date checked and the source, so the same research isn't redone.
- **Tools folder (2026-10-14):** Claude's helper scripts go in `.brain/tools/`, so every project has the same place for them instead of a new `claude-tools/` each time. Scripts that are part of what I'm making stay in the project. This repo's `tools/claude/` moved there.
- **An index in every folder (2026-10-14):** each folder has its own `index.md` listing its files, and the main `index.md` only lists the folders.
- **Indexes are built by a script, run by a hook (2026-10-14):** `~/.claude/skills/brain/brain_index.py` rebuilds every index from the files themselves, so they never drift. A hook runs it after every write in `.brain/` and at the end of each reply, because something that runs every time can't be forgotten. The format it reads is in the `brain` skill's `SKILL.md`.
- **The ideas index lists every idea, grouped by status (2026-10-14):** open, planned, done, dropped, so I can see the whole pipeline at once.
- **"Open right now" in the main index (2026-10-14):** plans with steps left and ideas not decided yet, so reading one file at the start of a chat is enough.
- ~~**"Backlog" or "bl" (2026-10-14):** means I've decided to do it, just not now.~~ Replaced 2026-10-14: I don't need a special word. When I say "do it later" or "worry about it later", that's it: a "later" plan, and the idea marked planned. Written in the global CLAUDE.md.
- **Phone and web for later (2026-10-14):** Claude Code on this PC first.
- **Haiku searches, the main Claude writes (2026-10-14):** a global `brain-search` agent (Haiku, read-only, in `~/.claude/agents/`) searches the brain and brings back the exact lines; the main Claude judges them. Writing stays with the main Claude, because it's the one that knows what I said and why; handing that to Haiku would cost as much as writing it. An agent fits better than a skill here, since it's a separate model with its own tools.
- **The brain replaces the mode notes (2026-10-14):** after looking at how notes were used in chatbot and jav: most of the notes were "where I stopped" and "next step", and thread sections got overwritten, so test results and known issues were lost. Decisions:
  - A live thread is a plan file that starts with `Where I stopped:` and `Next step:`. Checkboxes are optional, so a light thread like "play the first message" fits too. The main index shows each plan's next step.
  - Design files also hold "Confirmed working" and "Known issues", so they survive when a plan ends.
  - Measurements, research and setup commands go to `knowledge/`. Proposals sitting in design files move to `ideas/`.
  - `.modes/personalize.md` stays: it's how a mode behaves in a project, not memory. What only one mode needs goes in `.brain/modes/<mode>.md`.
  - The three mode skills now write to `.brain/`. Moving jav's and chatbot's old notes into a brain happens per project, later.
  - ~~In this repo, mode notes stay in `.modes/notes.md`, because they're about my life.~~ Replaced 2026-10-14: the mode notes here are part of the work too, so they moved into the brain.
- **`.modes/` is only `personalize.md` (2026-10-14):** right now is the chat, anything older is the brain, and `personalize.md` says how the modes work. So `.modes/notes.md` doesn't exist anymore, in any project.
- **`queue/` and `goal/` merged into the brain (2026-10-14):** they were an older memory system. To-dos and live threads became plans, parked threads became thoughts, goals became `design/goals.md`, and agenda, goals and Omar prep now read the brain.
- **`memory/` moved into the brain (2026-10-14):** in this repo, what Claude knows about me (memories, therapy summaries, insights, the reps log) now lives in `.brain/memory/`, so everything is in one place and `brain-search` can search it. Claude had suggested keeping it separate (journal = what I said, memory = who I am, brain = what I'm working on); I chose one place. It keeps its own hand-written index, which the script doesn't touch.
- **The end-of-reply hook rebuilds every brain next to this one (2026-10-14):** in a VS Code workspace with several root folders, a brain file in another project written through the shell would otherwise never get its indexes rebuilt. So at the end of each reply, the script also rebuilds the brains in the sibling folders of the current project.
- **What goes where (2026-10-14):** global CLAUDE.md = rules about me in every project (now including the "Where things go" list); a project's CLAUDE.md = how Claude works there whatever the mode; `.modes/personalize.md` = only what a mode does differently; the brain = facts, never instructions; a skill = step-by-step rules for repeated work. Applied to all three projects after Haiku audits. Here: `how-to-work-with-me.md` deleted (already in CLAUDE.md), the origins moved to `memory/background.md`, the apps list to `memory/self/apps.md`, Omar prep to `prompts/omar-prep.md`.
- **Subagents (2026-10-14):** Haiku subagents always run at low effort. A job too big for one Haiku agent to stay under 100K tokens (where Haiku costs 5x, `knowledge/claude-pricing.md`) goes to a Sonnet supervisor ~~at low effort~~ (replaced 2026-10-20: at medium effort, see below) that splits it into smaller Haiku agents. When a subagent's output is wrong: fix the output if I just want the result; fix the agent's prompt if the point is a reusable agent, and re-run only when I say so. Rules in the global CLAUDE.md.

When one does, the supervisor is Sonnet at medium, and Opus judges the supervisor. Why: a supervisor's whole job is judging what the Haiku agents bring back, and effort pays off on judgment; Sonnet at low scores below Haiku at high on the Intelligence Index (36 vs 38), so it's only worth paying for at medium (`knowledge/claude-pricing.md`).~~ Replaced 2026-10-24, see below.
- **Model tiers (2026-10-24):** the main chat (Opus) plans, judges and supervises. Writing work (code changes, file edits, rewriting skills or notes from a plan) goes to a Sonnet subagent at medium effort. Haiku at low effort does repetitive or simple tasks (searching, many similar small jobs). A Sonnet supervisor splitting big repetitive work into Haiku agents is still fine. Why: I found that Sonnet at medium effort is good at making code changes and writing; Opus is best at planning. So Opus plans and supervises, Sonnet medium does the writing, Haiku does repetitive tasks. Rule in the global CLAUDE.md.
- **No built-in memory (2026-10-14):** Claude Code's own memory folders were sorted by Haiku and deleted. Still-useful rules moved to the global CLAUDE.md (shell quirks, connectors, subagents, a clearer git rule: commits go to master, each project's CLAUDE.md says when to commit) and to chatbot's CLAUDE.md (content lines, scene and outfit prompts, commit-merge). The rest was already covered or stale; the Witchbreeding "her no is absolute" rule was dropped.
- **The rules for the brain go in the global CLAUDE.md (2026-10-14):** `~/.claude/CLAUDE.md` is read in every Claude Code chat on this PC, so how to write and run the brain is written there once, not in each project.
- **dot-claude has its own brain (2026-10-14):** the facts and decisions behind the global setup (the brain, plans, dotfiles, cloud sessions, pricing) moved from claude-assistant's brain to `~/.claude/.brain/`, because a chat in another project, or a cloud session on another repo, couldn't find `claude-assistant/...`. `~/.claude` exists on every machine, so the global CLAUDE.md points there. The plans, ideas and thoughts that built it stay in claude-assistant.
- **What the global brain holds (2026-10-14):** facts about the global setup from any project: the reasons behind the global rules, skills, agents, hooks and settings, how dot-claude syncs, research about Claude Code and the models, and plans and ideas for changing the global setup. Anything about one project or about me stays in that project's brain. Written into the global CLAUDE.md's "Where things go" so every chat knows.
- **A handoff skill for moving to a new chat (2026-10-18):** I often end a long chat with "put it all in the brain", start a new chat and tell it to read the brain and continue exactly where we left off, right before I said to save. Doing that by hand each time was repetitive, so it's one global skill, `skills/handoff/`, with two halves: save (first a catch-up of the last stretch: what was said since the brain was last written goes in, each in its folder, checked against what's there, since the brain is written live but the last few messages often aren't in it yet (added the same day; ~~the whole chat from the first message~~ Replaced 2026-10-18: only the last stretch, the rest is already written live); then every touched plan's Where I stopped and Next step rewritten for a fresh chat, the last open question word for word with its options, unrecorded decisions to design/, a `## Last stop` block above the marker in `.brain/index.md`, commit by the project's rules) and resume (read the Last stop and the one plan it names, check recent commits, then ask the open question again or start the next step). Global, because I do it in every project; first used in chatbot the same day. Claude can call it on its own too (asked the same day): save when a long chat may soon be summarized, after a big piece of work is committed, or when I say I'm stopping; resume when a chat opens with no request and there's a Last stop. Replaced 2026-10-24, see below: the catch-up, the plan rewrites, the Last stop block and the saving on its own are gone.
- **Handoff is lightweight (2026-10-24):** save writes only `.brain/handoff/handoff.md` (date and time, what the chat was doing, where it stopped, the next step and its plan file, any unanswered question word for word, setup), then commits and pushes. Resume reads that file and the plan it names, then wipes the file. Save only when I ask; Claude no longer saves on its own. Projects not migrated yet keep an old `## Last stop` block, which resume uses once and removes. The index script ignores `handoff/`. Why: handoff was using too much usage by re-reading the chat and sweeping six brain folders, and the brain is already written live.

Why: a chat in claude-assistant about my global setup didn't see the global brain, so a new chat wouldn't have known where things stood. For now only the repos in serina-sketch (and `~/.claude`) have a brain. A rule alone can be skipped, so a hook (`skills/brain/brain_peek.py`, before Read, Edit, Write, Glob and Grep) feeds the index into the chat the first time it touches that repo, once per repo per session.
