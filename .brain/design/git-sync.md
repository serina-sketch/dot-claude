# Git auto-sync across repos

- **Decided 2026-10-15:** every repo pulls `master` automatically, through hooks, not just a written rule. Why: I now work in about five repos at once (five folders in one VS Code workspace), on the PC and in cloud sessions at the same time, and the copies drifted out of sync. Too much to track by hand.
- **Pull automatically** rather than only warning (my choice, 2026-10-15).

- **Only at session start, only the workspace folders (decided and built 2026-10-15):** the sync runs once when a chat starts, and covers only the folders in the repo's `.code-workspace` file plus `~/.claude`, not every repo in the serina-sketch folder. No sync before commits or after pushes. Why: the full sweep took about 11 seconds before every commit, and claude-assistant commits after every write. The problem I actually want solved is a PC chat starting on a stale copy after I changed something in the cloud (or the other way round). Cloud sessions already start from a fresh clone, and git itself refuses a push when `master` has moved, so the pull at the start is the only part that's needed.
- **Always one line (2026-10-15):** the sync always prints a line at session start, even when nothing was pulled ("Git sync: N repo(s) up to date (…)"). Why: a quiet run looked the same as no run, so I couldn't tell whether the hook had fired.
- **Long sessions (2026-10-15):** two sessions writing to the same repo at once can still collide, and no tool fixes that. I'm moving away from long chat sessions anyway: the brain carries the context, so a new chat picks up where the last one stopped.
