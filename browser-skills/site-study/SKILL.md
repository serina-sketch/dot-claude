# Site study

The user is building their own app and wants to copy the UI flow and layout of an existing website. Your job is to explore the site and describe it in enough detail that they can rebuild the same experience on top of their own data. This is for their private use.

## Before you start

- You need two things: the **URL** and the user's **goals** (what they are building, what their data is like, which parts of the site matter to them). If the goals are missing, ask for them in one short message before exploring. A few lines is enough.
- Use the goals to decide where to dig deep. Screens the goals care about get full detail; screens that only matter for multi-user, accounts, billing or server admin get one line or are skipped.

## Rules while exploring

- Only look and play: open pages, click through, play media, open viewers and menus.
- Don't change settings, buy anything, submit forms, post, edit or delete anything.
- If a login is needed, look for demo credentials on the page or in the site's docs. If there are none, tell the user and stop. Never create an account or use the user's own accounts.
- If something needs a specific kind of item to show (e.g. a video, a file with subtitles), try to find one and say which item you used.

## For each screen

Describe on a wide desktop window:
1. **Layout**: what is where, rough proportions (e.g. "cover left, 1/3 width"), what stays fixed while scrolling.
2. **Elements**: every visible element and button.
3. **Interactions**: what clicking/hovering each one does, where it leads, any menus, keyboard shortcuts you notice.
4. **Look**: colors, theme (light/dark), density, typography feel.
5. **Nice touches**: anything that feels especially pleasant or clever.

Then shrink the window to phone width and say what changes.

Cover the navigation (menus, sidebars, how they open and collapse) and every main screen the goals touch. If the user listed specific screens or questions, go through those in their order.

## Report

Write it as one structured report with a heading per screen, then end with:
- **Main flow**: the core path step by step (e.g. open site → find an item → use it).
- **5 things that make it pleasant to use.**
- **Confusing or annoying parts.**
- **What to do differently given the user's goals**: concrete suggestions where their data or needs differ from what the site assumes.
- **Screenshots** of the key screens, if you can share them.

Be concrete and specific; "a grid of 4 cards per row with cover, 2-line title and circle name" beats "a nice grid of works".
